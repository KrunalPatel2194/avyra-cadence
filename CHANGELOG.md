# Cadence — changelog

Append a one-line entry after any non-trivial change. Newest at top.

## 2026-05-24

- Scaffolded subproject: folder tree (`services/cadence-api/{db,gmail,llm,push,routes}`, `mobile/`), `CLAUDE.md` index, this changelog. Plan at `~/.claude/plans/okay-you-are-working-agile-eich.md`.
- Renamed folder `cadence/` → `avyra-cadence/` for consistency with other Avyra subprojects.
- Added `cadence` domain to ai-engine: `avyra-voice-assistant/config/domains/cadence/` with `domain.yaml` + 4 prompts (`system.md`, `summarize.md`, `extract_tasks.md`, `daily_digest.md`). Non-conversational domain — bypasses intent_classifier/dialogue_manager; intended for direct `/api/cadence/*` routes (next step).
- Added `/api/cadence/*` routes to ai-engine (`avyra-voice-assistant/services/ai-engine/routes/cadence.py`): `POST /summarize`, `POST /extract_tasks`, `POST /digest`, `GET /health`. Self-contained Ollama client (num_ctx=8192–12288, JSON mode) — does not share the voice singleton. Bearer auth via `AI_ENGINE_SHARED_SECRET`. Wired into `main.py` via `app.include_router(...)`; `/admin/reload` now also clears cadence prompt cache. Set `AI_ENGINE_SHARED_SECRET=<value>` on the ai-engine container before deploying.
- Scaffolded `cadence-api` (FastAPI :8010): `main.py` (lifespan bootstraps schema), `config.py` (pydantic-settings), `db/{schema.sql,models.py,session.py,init.py}`, route stubs (`auth/tasks/emails/devices/digest`), `Dockerfile`, root `docker-compose.yml` (Postgres on 5433), `.env.example`. Schema includes source-polymorphic `tasks` (email/news/manual) and reserved v2 `news_sources` / `news_items`. Refresh tokens stored Fernet-encrypted in `users.google_refresh_token_enc`. Gmail poll interval defaulted to 2h (7200s) per user policy.
- Wired Google OAuth + JWT auth: `security/crypto.py` (Fernet), `security/jwt.py` (HS256 issue/decode + `current_user` FastAPI dep), `gmail/oauth.py` (PKCE code exchange + id_token verify + gmail scope check), and real `routes/auth.py` (`POST /auth/google/exchange`, `GET /me`, `POST /auth/revoke`). On re-auth Google may omit refresh_token — we only overwrite when one is actually returned, never null out a working token. First-time sign-in without a refresh token returns 400 telling the client to retry with `prompt=consent`.
- Wired tasks CRUD (`routes/tasks.py`): `GET /tasks` with status/due/source filters, `POST /tasks` (manual only — source_type forced server-side), `PATCH /tasks/{id}`, `DELETE /tasks/{id}` (hard-delete manual; soft-delete LLM-extracted via status='deleted' so re-ingestion doesn't resurrect them). Ordering: open+dated first by due_date asc, then undated, then completed.
- Added ai-engine HTTP client (`llm/ai_engine_client.py`): `AiEngineClient.summarize() / extract_tasks() / digest() / health()` with bearer auth + 180s timeout + JSON-only parsing. Process-wide singleton via `get_client()`. Wired emails routes (`routes/emails.py`): `GET /emails` (cursor pagination on received_at + per-email task counts in a single grouped query), `GET /emails/{id}` (detail + linked tasks excluding soft-deleted), `POST /emails/refresh` (returns 202 stub for now — wires to watcher in Step 8; returns 409 when Gmail isn't linked).
- Built Gmail watcher: `gmail/client.py` (sync google-api-python-client, payload tree walk, HTML→text via beautifulsoup4, body cap 12k chars, query `after:<unix> -in:chats -from:me`, max 50 msgs/poll) + `gmail/watcher.py` (async `poll_user(user_id)` orchestrator: fetch via `asyncio.to_thread` → upsert via `ON CONFLICT DO NOTHING` on (user_id, gmail_msg_id) → summarize → extract_tasks → bump `last_polled_at`). Promo/forum-labeled mail is stored but never sent to the LLM. LLM-extracted tasks with confidence <0.55 land as `status='snoozed'` (suggestions). Per-user `asyncio.Lock` prevents scheduled poll + manual `/emails/refresh` from double-ingesting. `POST /emails/refresh` now actually fires `poll_user` via FastAPI BackgroundTasks (202).
- Added APScheduler (`scheduler.py`) with 4 jobs (started in lifespan): `gmail_poll_all` every 2h, `digest_tick` every 5min (per-user local-hour check), `overdue_sweep` every 1h, `reminder_tick` every 60s. Built `digest.py` (assembles 24h emails + open + overdue tasks, calls ai-engine `/api/cadence/digest`, upserts to `digests` via `ON CONFLICT DO UPDATE`, sends APNs). Wired `push/apns.py` (token-based auth, aioapns; no-op when creds absent — dev/simulator-safe). Real `routes/devices.py` (`POST /devices` upsert, `DELETE /devices/{token}`) and `routes/digest.py` (`GET /digest/today`, `POST /digest/generate`).
- Scaffolded mobile (`mobile/`, Expo prebuild + expo-router + TypeScript): `package.json`, `app.json` (bundle `com.avyra.cadence`, scheme `cadence`, notifications plugin), `tsconfig.json`, `babel.config.js`, `eas.json`, `.env.example`. Source under `src/`: `config.ts`, `theme.ts`, `api/{client,types,hooks}.ts` (TanStack Query, JWT via expo-secure-store), `auth/{google,session}.ts` (expo-auth-session PKCE + Zustand session store), `push/register.ts` (iOS APNs token registration), `components/{TaskRow,EmailRow}.tsx`. Routes under `app/`: `_layout.tsx` (AuthGate redirects), `index.tsx`, `(auth)/sign-in.tsx`, `(tabs)/{tasks,inbox,digest,settings}.tsx`, `email/[id].tsx`, `task/new.tsx` (modal). Tasks screen has unified list + filter chips + floating + button; New-task modal supports title/notes/due/time/priority. Inbox is pull-to-refresh, email detail shows summary + extracted tasks + full body. Digest renders markdown via react-native-markdown-display. Mobile README documents the full setup sequence. **iOS app is ready to `npm install && npx expo prebuild --platform ios && npx expo run:ios`.**
